# Repo Audit — Raid Mech Announcer — 2026-05-07

## Executive summary

- The Rust backend carries a **large fork-residue from `snoww/loa-logs`**: `live/`, `local.rs`, `utils.rs`, `models/*`, `api/*` are gated behind `meter-core` and many ride `#![allow(dead_code)]`. The `meter-core` build path is currently **broken** — `live/mod.rs` imports `crate::database::*` (no such module) and `crate::api::{StatsApi, BanList, HeartBeatApi}` (not defined in `api/args.rs`). Either resurrect or delete; today it is dead-on-purpose code that won't compile if anyone flips the flag.
- The frontend `AppSettings` interface (in `src/lib/settings.ts`, defaulted in `stores.svelte.ts`) is bloated DPS-meter cruft. Only ~5 fields are actually read (`accentColor`, `scale`, `logScale`, `betaChannel`, `shortcuts.hideMeter`). Whole `meter`, `logs`, `buffs` sub-trees and 40+ `general` fields are dead at the read site, even though the settings file/localStorage round-trips them all.
- ~13 unused TypeScript exports (mostly settings interfaces and `Misc`/`UpdateInfo` companions) — low-risk noise but worth tidying.
- 1 stale frontend import: `mechStore` imported but unused in `mech-overlay/+layout.svelte`.
- Counts: **0 fully-orphaned source files**, **~17 unused exports**, **~1 stale import**, **~6 dead code paths (Rust + TS)**, **~7 restructure suggestions**.

## Orphaned files

No frontend source files were found that nothing references. The grep for each `.svelte`/`.ts` basename turned up at least one consumer (or it is itself a SvelteKit root such as `+layout.svelte`/`+page.svelte`).

The Rust side has no unreferenced files at the file level either — every module under `src-tauri/src/` is named in `main.rs`'s `mod ...` block or transitively included. **However**, several files are effectively orphaned at runtime in the open build (`meter-core` feature off):

- `src-tauri/src/live/*.rs` — gated behind `#[cfg(feature = "meter-core")]`. Confidence: high.
- `src-tauri/src/local.rs` — same gate. Confidence: high.
- `src-tauri/src/api/args.rs` — `GetCharacterInfoArgs::new` is only consumed by `live/`. `SendHeartbeatArgs` has no consumer in this repo at all. Confidence: medium (used to be wired to a stats backend that's been deleted).
- `src-tauri/src/utils.rs` — every public function is consumed by `live/` only. The whole file is dead in default builds. Confidence: high (file is `#![allow(dead_code)]`).
- `src-tauri/src/models/*.rs` — `data.rs` is partially live (`AssetPreloader` reads game JSON), but `encounter.rs`, `entity.rs`, `skill.rs`, `status_effect.rs`, `misc.rs` only feed `live/`. Confidence: high.

  Suggested action: either commit to restoring the stats-API path (and fix the `crate::database` / `crate::api::StatsApi` import errors) or delete the live/local/api/utils/models surface in a single sweep. Half-measures hide the breakage.

## Restructure suggestions

1. **`AppSettings` is a DPS-meter fossil.** `src/lib/settings.ts` describes a 100-field schema (general/meter/logs/buffs/shortcuts/breakdown) inherited from `loa-logs`. The mech-announcer reads ~5 of them. A fresh reader will burn time figuring out which knobs are real. Suggested move: collapse to the live fields (`accentColor`, `scale`, `logScale`, `betaChannel`, two shortcut bindings) and migrate the persisted JSON in one shot. The `MeterSettings`/`LogsSettings`/`BuffSettings`/`BreakdownBase` interfaces would all disappear.

2. **Two parallel settings stores.** `stores.svelte.ts` (`settings`/`AppSettings`) and `mech-store.svelte.ts` (`mechSettings`/`MechSettings`) both manage settings independently — different persistence keys (`appSettings` vs `mech-announcer-settings`), different reactivity patterns (class with `$effect.root` vs IIFE). A fresh reader has to learn both. Once `AppSettings` is slimmed (suggestion 1), consider folding the survivors into `MechSettings` and deleting `stores.svelte.ts`'s `Settings` class.

3. **Name collision: `difficultyMap`.** `src/lib/constants/encounters.ts:184` exports a `difficultyMap` string array (LOA Logs difficulty enum names) and `src/lib/mech-store.svelte.ts:150` defines a `difficultyMap` `$state` (raid name → difficulty selection). Same name, unrelated meaning. The constants-file one is also unused (see Pass B). Renaming or deleting it removes a tripwire.

4. **`encounters.ts` is mostly cruft.** Of its 5 exports (`encounterMap`, `bossHpMap`, `difficultyMap`, `raidGates`, `bossList`), only `bossHpMap` is consumed externally. The file lives under `src/lib/constants/` even though it overlaps heavily with `src/lib/data/raid-library.ts`'s `LIBRARY` (which has its own per-gate boss list). Consider folding the surviving `bossHpMap` into `raid-library.ts` near the `releaseOrder` metadata it logically belongs to, and deleting the constants/encounters file.

5. **`overlays/_shared.ts` naming.** SvelteKit treats files prefixed with `_` as private to that route — fine when imported only locally, but it's an unusual signal in a `$lib/components/` subtree where other helpers don't follow this convention. Consider renaming to `overlay-utils.ts` for consistency.

6. **`gateLabel` inlined in two places.** `GateSidebar.svelte:57` and `ImportRaidsModal.svelte:30` each define `gateLabel(gate: number)` with the same body that already exists in `mech-constants.ts`'s `formatGate`. Two of the three are wrappers around the third. Keep one — preferably make `formatGate` produce the user-facing `Gate 2.1` form directly, or expose a single `gateLabel` helper from `mech-constants.ts`.

7. **Rust dead-fork sweep.** As described in Executive Summary: `live/`, `local.rs`, `utils.rs`, `models/*` (except `data.rs`'s `AssetPreloader` consumers), `api/*` exist only to feed a packet-capture pipeline that doesn't compile. The CLAUDE.md acknowledges this ("`meter-core` feature is private — open builds use `meter-core-stub`") but the stub doesn't paper over the missing `crate::database`/`crate::api::StatsApi` references. Recommendation: either restore the dependencies (would require a `database` module and the `StatsApi`/`BanList`/`HeartBeatApi` types) or delete this entire fork-residue surface in one PR. The current state is the worst of both worlds: a feature flag that's "off but pretending to be on."

## Notes / caveats

- **Did not verify** outbound consumers — this repo is the leaf of a Tauri desktop app and has no `package.json` `exports`/`main` for downstream npm consumers, so unused TS exports really are unused.
- Findings assume the **default Cargo features** (no `meter-core`). If you turn `meter-core` on, the current source tree fails to compile (missing `crate::database`, missing `StatsApi`/`BanList`/`HeartBeatApi`). I treated `live/` etc. as dead because under no current build configuration does this code execute.
- I did not check inline CSS or asset usage (`static/favicon.png`, font files). All survivor-status checks were against TS/Svelte/Rust source only.
- Skipped TODO/FIXME scans by design (per skill contract). The CLAUDE.md TODO list at the top of the repo enumerates the updater/donation/Discord placeholders that intentionally remain.
- Some "unused export" claims about `src/lib/settings.ts` interfaces (`GeneralSettings`, `MeterSettings`, etc.) are marked medium-confidence because TypeScript convention often exports nested interfaces even when only the umbrella is consumed externally. Whether they should be slimmed is downstream of restructure suggestion 1.
